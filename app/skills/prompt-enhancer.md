# Prompt Enhancer — AI工作办公适配版

## 来源与实现边界

方法参考：krunalkanojiya22/prompt-enhancer，所查阅 SKILL.md 标注版本 2.0。
https://github.com/krunalkanojiya22/prompt-enhancer/blob/main/SKILL.md

本项目以独立中文指令适配其意图澄清、任务分类、按复杂度组织提示词、输出要求及自检的方法；没有原样复制上游完整 SKILL.md，也不是安装 Claude/Codex 插件。实际运行指令位于 `web-src/core.js` 的 `promptEnhancer(skill)`，经构建嵌入 `assets/core.js`，随 APK 离线携带；调用仍使用用户配置的 DeepSeek 服务。

## 生效位置

全部 8 个办公工作流共用，只有 `messages('optimize', ...)` 加载该指令。它不是第 9 个业务工作流，不新增选择入口。执行及格式修复阶段继续使用原有提示词，原始任务仍优先。

用户输入 → Prompt Enhancer 整理执行任务书 → 原有 AI 执行/格式校验 → 导出成果。

不新增 AI 调用轮次；正常情况仍是优化和执行两次请求，原有一次格式修复机制不变。手动确认开启时，仍可修改优化后的任务书再执行。

## 办公适配规则

- 根据简单、一般、复杂任务采用不同长度，避免一句话需求变成冗长模板。
- 任务书按需组织角色、任务、输出要求、背景材料、验收条件等中文栏目。
- 注入当前工作流的具体规则，例如 Excel 数字和空白数据要求、PPT 讲稿要求、会议纪要的待确认事项。
- 保留原始数字、专有名称和明确限制；缺失的业务事实标“待补充”。组织形式可采用明确说明的默认值，不虚构业绩或资料。
- 已有提示词只修补需要的部分；后续修改以当前消息为准，保留仍有效的约束。
- 自动流程只产出一份执行任务书，不加入上游交互式开场、改写理由、模型介绍或追问，避免下一步再次优化而没有工作成果。
- 只分析实际提供的资料；不声称已经联网、读取文件或生成成果。不输出思维过程。

## 验证边界

`npm test` 包含优化指令路由、材料保留、两步状态机、执行/修复消息与既有版本对照、无关生产文件哈希等测试。浏览器测试使用固定响应，检查请求内实际携带新指令，不调用真实服务。

这些验证证明代码已接入和原流程未回退，不代表对真实模型效果作出保证。按用户要求，真实 Key 和真实生成效果由用户验证。
